PLATFORM OPERATIONS & BUSINESS LOGIC BLUEPRINT

Detailed Breakdown of Behind-The-Scenes Rules and Interactive Button Logic
SYSTEM WORKFLOWS, FEASIBILITY METRICS, AUTO-CALCULATIONS AND SETUP CONFIGURATIONS

1. FEASIBILITY ALLOCATION ENGINE RULES

The platform embeds three discrete allocation strategies to calculate sample sizes and target CPIs across available panels. These rules maintain consistency across tabs:

A. Cost-Optimized Strategy (Cheapest CPI First)

  • Internal Maximization: The algorithm always satisfies demand first using the Internal Panel (proprietary pool) up to the specified maximum internal percent ceiling (default is 100%, or user-defined).
  • Internal 90% Near-Limit Diversity Rule (System Enhancement): If the effective internal capacity can satisfy the target sample size but is within 10% above the target (effective internal capacity ≥ target and ≤ target × 1.10), the engine automatically limits internal allocation to 90% of the target. This forces the remaining 10% to be allocated across external vendors, ensuring panel diversity and preventing single-source exhaustion.
  • External sourcing: Any remaining unfilled quota is routed to active external Vendors. The vendors are sorted in ascending order based on their Cost Per Interview (CPI) rates.
  • New Additional Rule (Similar Costs Tie-Breaker): If there are 2 vendors with similar costs (within $0.001), prioritize the capabilities (highest capacity) first, then the tier (Tier 0 > Tier 1 > Tier 2 > Tier 3). If both cost and tier match, quality color flag acts as fallback: Green > Yellow > Orange.
  • Single Covering Vendor Preference: Prior to splitting quota among multiple vendors, the engine checks if a single candidate vendor can cover 100% of the remaining unfilled sample at a valid CPI. If one exists, it is prioritized to minimize multi-supplier overlap penalties.
  • Cap Boundaries: The engine will allocate up to the maximum vendor capacity. If additional demand remains, it falls over to the next cheapest vendor.
  • Targeted CPI Cap Enforcement: If a targeted CPI limit is defined on the row (Targeted CPI > 0), any vendor whose cost per interview exceeds this threshold is strictly excluded from automated allocation.

B. Tier Priority Strategy (Quality Vetting Model)

  • Internal Maximization: Starts by exhausting the Internal Panel (proprietary pool).
  • Vetting Tiers: Remaining sample sizes are assigned based on strict Vendor Tiers: Tier 0 (Vendor 1), followed by Tier 1 (Vendor 2), Tier 2 (Vendor 3), and Tier 3 (Vendor 4).
  • Tier Hierarchy & Unassigned Vetting: Suppliers from the database pool without an assigned tier default to Priority Level 4 (placed strictly behind Tier 3).
  • Quality Sorting: If CPIs differ within the same Tier, cheaper CPIs are prioritized. This guarantees highest programmatic panel quality.
  • New Additional Rule (Quality Sorting Precedence): If 2 vendors have similar costs, prioritize capabilities. The full sorting precedence evaluates: (1) Vendor Tier > (2) Quality Color Flag (Green > Yellow > Orange) > (3) Lowest CPI > (4) Capabilities.

C. No Internal Cost Strategy (Bypassed Proprietary Pool)

  • Zero Internal Allocation: Bypasses the Internal Panel completely, forcing its allocated sample to exactly 0 to study external-only panel procurement impact.
  • Fallback Sourcing: Routes 100% of the target sample structure to the paid external Vendors using cheapest-first CPI.
  • New Additional Rule (Same Costs Tie-Breaker): If external vendors have the exact same CPI, the engine prioritizes capabilities first (highest capacity), followed by Tier priority and quality color flag, ensuring maximum project feasibility.

D. Composite Overlap Penalty Calculations

  • Mechanism: Active panel overlap degrades real-world capacity. The engine assesses separate utilized programmatic streams.
  • Scale of Penalties: 1 utilized panel = 0% penalty. 2 utilized panels = 20% penalty. More than 2 utilized panels = 20% + 5% additional increment per supplier, capped at a maximum ceiling of 50% (1 panel = 0%, 2 panels = 20%, 3 = 25%, 4 = 30%, 5 = 35%, 6 = 40%, >6 = 50%).
  • Capacity Impact: Effective capabilities and caps are reduced by multiplying raw volumes with (1 - penalty percentage). The engine iterates up to 10 cycles to converge allocations stably.
  • New Additional Rule (Universal Overlap Scope): The overlap impacts all the max potential feasibilities when applicable, including the internal one; the overlap, once applied, is applied on all potential capabilities from all the vendors. Cumulative Max Potential = (Internal + Σ Vendor Capacities) × (1 - Overlap Penalty %).
  • Grid Column Overlap Representation: In the Database Grid, Vendor Max % columns dynamically display the overlap-penalized feasible capacity (rawCapacity × slider% × (1 - overlap%)). The Internal Max % column displays raw unpenalized database ratio (internal / target) unless a custom maximum internalization ceiling is applied.
  • Manual Overlap Override: Each row features an interactive Overlap dropdown allowing procurement leads to force fixed overlap values from 0% to 50% (in 5% increments) or leave on 'Auto' for dynamic formula calculation.

2. INTERACTIVE BUTTON WORKFLOWS & ACTIONS

Behind each interactive button is a strict set of logical action sequences. The categories of rules for key buttons are defined below:

A. 'Download BRD Document' Button (New Functional Requirement)

  • Purpose: Instantly compiles and downloads an executive-ready Business Requirements Document detailing backend frameworks, pseudocode, and firestore rules.
  • Logic Flow: Interrogates the active pitches and allocations, formats tables, and exports a raw .docx file entirely client-side with no external Google Drive dependencies.
  • System Navigation & Location: Currently accessible via the top-header 'Settings' dropdown menu labeled as Download BRD (.docx). An optional 'Create BRD in Google Docs' action is available when Google Workspace OAuth is connected.

B. 'Download Setup Manual' Button (New Functional Requirement)

  • Purpose: Generates this functional and administrative setup guide.
  • Logic Flow: Renders the categories of rules, calculations, and button action flows, delivering it directly to the local download folder.
  • System Navigation & Location: Currently located inside the header 'Settings' dropdown menu labeled as Download Setup (.docx). It is accompanied by a companion Download Board Deck (.pptx) button for executive slide deck exports.

C. 'Check Feasibility' Button

  • Purpose: Performs active lookup auditing against capabilities databases.
  • Logic Flow: Pulls live supplier capacity sheets. If offline, it queries the locally uploaded database, computing filled sample percentages, blended CPI rates, operational profits, and alerts completion.
  • New Additional Rule (Capability Deduplication & Priority): When checking for similar specs, if a vendor has different feasibilities in the database, higher/lower capabilities for the same specs, the higher capabilities will be prioritized. The system won't multiply the capabilities, using the same vendor's capabilities from multiple rows; it will be used only once per option.
  • Three Distinct Evaluation Modes: The button provides a dropdown selection with 3 specialized workflows: (1) Feasibility for Targets (exact scenario targets), (2) Feasibility for Options (multi-scenario evaluation across pitch variations), and (3) Feasibility Optimized (unconstrained optimization across all 43 suppliers in the pool).
  • Manual Overrides Safeguard Modal: If manual overrides are active (custom panel blends, CPI overrides, or internal caps), clicking Check Feasibility triggers a confirmation prompt offering 'Reset & Run' (reverting to pure database defaults) or 'Keep & Run' (preserving custom user adjustments intact).

D. 'Add New Vendor' Button

  • Purpose: Allows procurement leads to discover and enroll additional programmatic suppliers to tackle unfilled country deficits.
  • Logic Flow: Identifies active countries in specifications, compares them against unassigned suppliers inside the static Vendor Database Pool, selects the best matching vendor covering the highest number of active countries in your pitch, and appends the new supplier to the active workspace registry.
  • New Additional Rule (Zero Share Allocation): The new supplier won't affect the current feasibility, it will have 0% share allocated, it will be used when manual share will be allocated.
  • New Additional Rule (Database Capabilities & CPI): The new suppliers will have their potential capabilities and prices from the database (same as the other ones).
  • New Additional Rule (Overlap Impact on Max Feasible): Its capabilities will be added to the max feasible for each row and it will be impacted by the overlap (if overlap is applied).
  • Candidate Waterfall Algorithm: The system selects candidates using a strict 4-stage hierarchy: (1) Country Coverage Match Count > (2) Vendor Tier Quality (Tier 0 > 1 > 2 > 3) > (3) Quality Color Flag (Green > Yellow > Orange) > (4) Total Feasibility Volume.
  • Exhaustion Toast Alert: If no unassigned pool vendors cover active pitch countries, or all 43 suppliers have been added, the system displays an immediate notification: 'No vendors available'.

E. 'Reset / Clear All Overrides' Button

  • Purpose: Clears user-defined manual modifications to reset the optimization formulas.
  • Logic Flow: Resets all manual percent overrides (reverting to auto-allocation), clears custom maximum internalization values, and handles database clear-outs with optional backup recovery storage under the user's history dropdown.
  • Interface Label & Actions: Implemented in the Database Grid header as 'Reset Defaults'. Clicking opens a modal providing 'Save & Reset' (prompts for backup name, stores in local storage) and 'Reset Without Saving' (reverts to factory defaults).

3. HIGH-DIALECTIC RUNTIME LOGIC

A. Real-Time Automatic Re-checking

To eliminate manual effort, any manual coordinate or specifications adjustment (such as typing a new country name, modifying target sample size, changing LOI values, or altering incidence index percentage) instantly and seamlessly triggers a silent, background feasibility check. This guarantees that your financial charts, total metrics, filling rates, and feasibility allocations are kept dynamically synchronized with zero friction.

  • Toolbar Placement Specification: This will become a button on/off, called Live Feasibility - that will be added right after Insert Specs and Check feasibility (the button will be moved a little bit to the left, to have the same format as is now). When on, it will do the background feasibility check; when off, the Feasibility optimized button has to be clicked to start the assessment.
  • Current Codebase Note: Live Feasibility is currently integrated within the Settings dropdown menu (Settings > Feasibility Mode). Moving it to the main toolbar beside Insert Specs completes this UX requirement.

B. Country Autocomplete Dropdown

Input text fields for Country and Market are enriched with a universal Autocomplete feature. Users can type any fragment of a country name, and a responsive dropdown filtered in real-time will appear. This eliminates spelling errors and ensures proper capabilities lookup matching.

  • Global ISO Taxonomy: Powered by a standardized datalist (#country-datalist) containing all recognized global sovereign markets and territories.
  • Alphanumeric Normalization: User inputs and database records are normalized by lowercasing and stripping non-alphanumeric characters (.replace(/[^a-z0-9]/g, '')), ensuring seamless lookup matching across common variations (e.g. 'US' vs. 'United States', 'UK' vs. 'United Kingdom').
